# Database rules

- The schema is learning-target code: I design it, you review it (level 1–2), unless I say "write it".
- Every schema change is an Alembic migration with a working downgrade. Never edit a migration that has already been applied.
- Read autogenerated migrations line by line. Autogenerate sees a renamed table or column as a drop plus an add, and it doesn't create partitions.
- Follow the partitioning decision in docs/decisions.md (ADR-002). On a partitioned table, primary keys and unique constraints must include the partition key.
- Every time column is `TIMESTAMPTZ`.
- Text-to-SQL and the agent read through views with a read-only role, never the base tables.
